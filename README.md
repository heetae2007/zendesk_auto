# Zendesk 문의 자동 접수

Zendesk 신규 문의를 1분마다 조회해 Claude로 요약·파트·세부업무를 분석하고, 기준표에 따라 개발 담당자와 당일 젠콜 PIS 담당자 1명을 정해 Telegram으로 알리는 웹 도구입니다. 설정은 Google Sheets에, 실행 이력은 서버의 `data/`에 저장합니다. 이 저장소는 **0.13** 구현입니다.

> 기본값은 **추천 전용**입니다. 실제 Zendesk 접수(양식·관련파트·운영팀 담당자·상태 변경과 공개 안내 등록)는 서버 `.env`의 `ALLOW_LIVE_WRITES=true`와 웹의 **실제 Zendesk 접수** 설정이 **모두** 켜졌을 때만 동작합니다. 실제 운영 계정에서는 아직 검증하지 않았습니다.

사용 방법은 [사용자 매뉴얼](docs/MANUAL.md)을 참고하세요.

## 처리 흐름

1. 운영 시간(기본 평일 09:00~18:00, 한국 시간)에 Zendesk에서 **신규** 티켓을 조회합니다. 주말·한국 공휴일·지정한 제외일과 운영 시간 외에 들어온 티켓은 다음 운영 시간에 처리합니다.
2. Claude가 문의와 비슷한 과거 사례를 보고 요약, 하나 이상의 **파트**, 파트별 **세부업무**를 정합니다. Claude는 사람을 고르지 않으며, 기준표에 없는 파트·세부업무를 반환하면 응답을 거부하고 재시도합니다(3회 실패 시 검토 대상).
3. **업무·담당자 기준표**에서 개발 담당자를 정합니다.
   - 세부업무의 주담당을 배정하고, 주담당이 부재·비활성·권장 업무량 초과이면 백업을 배정합니다.
   - 세부업무가 없거나 Claude가 고르지 못하면 **파트 기본** 담당자를 배정합니다.
   - 여러 세부업무가 해당하면 개발 담당자도 여러 명이 될 수 있습니다.
4. **운영 달력**의 당일 젠콜 중에서 PIS 담당자를 정확히 한 명 정합니다(아래 PIS 배정).
5. Telegram으로 알리고, 실제 접수가 켜져 있으면 Zendesk에 반영합니다.

검토 사유가 하나라도 있으면 '검토 필요'로 남기고 Zendesk는 변경하지 않습니다. 사유는 웹에서 확인합니다.

## 주요 규칙

### PIS 배정

- 운영 달력은 zendesk 배정표처럼 주마다 날짜 줄, 당직자 행(call 1~4 드롭다운), 비고 행으로 구성합니다. **call 2는 점심 당직**입니다. 날짜마다 당직자를 고르고, 쉬는 사람은 이름을 빼 둡니다(부재 체크는 화면에서 없앴지만 이미 저장된 부재 표시는 계속 배정에서 제외됩니다). call 4도 배정 대상이며, 비고는 연차·특이사항 메모로 배정에는 쓰이지 않습니다.
- **배정 비율**: '배정비율 표시'(브라우저별 설정, 기본 아니오)를 예로 하면 이름 옆에 비율(%)이 보입니다. 비워 두면 균등 배정이며 화면에는 100÷인원수가 미리 채워집니다. 직접 입력하면 합계가 100%(±1%)여야 하고, 숨겨 두어도 저장된 비율은 배정에 쓰입니다.
- 배정표 스크린샷은 Claude 이미지 분석으로 읽어 드롭다운(call 1~3, 부재자 제외)에 채우며, **젠콜 저장**을 누르기 전에는 적용되지 않습니다. 날짜가 불명확하거나 `#VALUE!` 등 오류가 있는 행은 날짜를 추정하지 않고 '날짜 확인 필요' 목록에 둡니다.
- **실시간 배정**: 당일 젠콜이면서 부재가 아닌 활성 인원 중, 그날 배정 비율 대비 당일 배정 건수가 가장 부족한 사람을 고릅니다.
- **점심 당직 규칙**: 배정하는 시각(티켓 생성 시각이 아님)이 12:00~13:00이면 call 2 담당자에게만, 13:00~14:00이면 call 2를 뺀 나머지에게만 배정하고, 그 외 시각은 아래 규칙 그대로입니다. call 2가 비었거나 부재이면 제한하지 않고, 13~14시에 다른 당직자가 없으면 PIS 없이 검토 대상이 됩니다. 사유에 '점심 당직 시간' 등이 표시됩니다.
- **밀린 티켓 배정**: '밀린 티켓 묶음 기준'(기본 0=사용 안 함) 이상이 한 번에 대기하면, 기준표 세부업무(없으면 파트 기본)의 PIS 담당 → PIS 백업 순으로 같은 묶음에서 한 사람당 한 건씩 배정합니다. 남는 티켓은 당일 젠콜 중 배정 비율 순서로 계속 배정합니다. 점심 당직 제한은 여기에도 적용됩니다.
- 분석한 모든 티켓(검토 대상·분석 실패 포함)에 PIS를 배정합니다. 젠콜이 아니거나 부재·비활성인 사람에게는 절대 배정하지 않으므로, 당일 젠콜이 없으면 PIS 없이 검토 대상이 됩니다.
- 배정 이력은 티켓당 한 줄로 저장해 재분석해도 중복 집계되지 않습니다.

### 개발 담당자 배정

- 기준표 세부업무는 과거 완료 티켓을 Claude로 업무 영역별로 묶어 추가할 수 있습니다(각 세부업무에 판단 기준 설명). 담당자는 그 파트 담당자 중 최근 처리 빈도로 정하며, 기존 세부업무의 담당자는 바꾸지 않습니다.
- 담당자는 **기준표 세부업무 담당 → 파트 기본 담당 → 과거 처리자** 순으로 정합니다. Claude는 파트·세부업무만 고르고 사람 이름을 정하지 않습니다.
- 과거 처리자는 맞는 세부업무도, 파트 기본 담당도 없을 때만 씁니다. Claude가 근거로 든 비슷한 과거 티켓(같은 파트)의 실제 처리 개발 담당자 중 가장 많이 맡은 사람이며, 이 경우 항상 검토 필요로 둡니다.
- 비슷한 과거 티켓을 보낼 때 실제 처리한 개발 담당자(`handled_by`, 명단에 있는 개발 담당자만)도 함께 보냅니다.
- 권장 업무량은 미해결 티켓의 운영팀 담당자 필드에 그 사람의 Zendesk 선택값이 들어간 건수로 셉니다. **선택값이 설정되지 않은 담당자는 업무량이 0으로 집계됩니다.**
- 동일인 여부가 확인되지 않은 유사 이름의 담당자는 기준표에 있어도 배정하지 않습니다.
- 특정 화면·메뉴가 명시된 문의는 규칙에 따라 파트별로 1명씩 배정합니다.

### Telegram

```text
[병원명] 파트 개발담당자 책임님 / PIS PIS담당자 책임님

문의 요약

티켓: #번호
```

여러 파트는 `/`로 이어 표시하고 **같은 담당자는 한 번만** 표시합니다. 한 사람이 여러 파트에 걸리면 비중이 높은 파트(주담당 > 협업 > 미정, 같으면 먼저 나온 파트)에만 이름을 붙이고, 담당자가 모두 다른 파트에 표시된 파트는 메시지에서 뺍니다. 주담당·협업·검토 필요 문구는 넣지 않습니다. 테스트 메시지에는 `[테스트]`와 '가상 티켓 (실제 Zendesk 티켓 아님)'이 붙습니다.

### 실제 Zendesk 접수 (켰을 때만)

- **검토 필요도 접수**(`live_include_review`): 켜면 검토 필요 티켓도 등록·접수 안내·담당자 배정까지 합니다. 개발 담당자가 없으면 PIS만 넣고, 긴급 의심 티켓은 제외합니다.
- **테스트 대상 제한**: `live_test_tickets`(티켓 번호)나 `live_test_hospitals`(병원명 옵션 이름)가 있으면 그 티켓·그 병원 티켓만 실제로 바꿉니다. 병원명은 Zendesk 필드 옵션에서 태그로 바꿔 비교하고(10분 캐시), 조회에 실패하면 아무것도 바꾸지 않습니다. 테스트 대상은 '테스트 접수' 버튼으로 검토 필요 추천도 접수할 수 있습니다.

- 검토 사유가 없는 신규 티켓에 `데이터 서비스` 양식, 관련파트, 운영팀 담당자(PIS 정확히 1명 + 개발 N명), `등록` 상태, 공개 접수 안내를 **한 번의 요청**으로 반영합니다. 안내 문구의 `[티켓번호]`는 실제 번호로 바뀝니다.
- 반영 직전 티켓을 다시 읽어 다음 중 하나라도 해당하면 변경하지 않고 검토 대상으로 둡니다.
  - 신규 상태가 아님
  - 최초 감지 이후 수정됨
  - 관련파트·운영팀 담당자 필드에 이미 값이 있음
  - 다른 양식이 지정됨(양식이 비어 있거나 계정 기본 양식인 경우만 변경)
  - 파트·담당자의 Zendesk 선택값이 없음
- Zendesk safe update(`safe_update`, `updated_stamp`)로 그 사이 사람이 수정하면 409로 거부됩니다.
- 티켓당 한 번만 시도합니다. 타임아웃 등 결과가 불확실하면 재시도하지 않고 '접수 결과 미확인'으로 두며, **결과 확인** 버튼으로 티켓을 다시 읽어 확정합니다.

### 검토·정확도

- 개발팀·젠콜 접수 현황 XLSX(티켓번호·요청병원·관련파트·개발담당자/PIS담당자·요청내용요약·Zendesk 실제상태 열)를 올리면, 각 티켓의 **첫 자동 추천**과 실제 기록을 비교해 일치 / 파트 오분류 / 담당자 변경으로 분류합니다. 처리완료 티켓만 정확도에 포함합니다.
- **일치는 추천한 개발 담당자와 실제 처리한 개발 담당자가 모두 같을 때만**입니다. 한 명이라도 빠지거나 더 있으면 담당자 변경입니다. 이전(한 명만 겹쳐도 일치)에 가져온 결과도 서버 시작 시 새 기준으로 다시 판정합니다.
- **담당자 정확도는 부분 점수**입니다. 티켓마다 실제 처리자 중 AI가 맞힌 비율(예: 실제 A·B·C·D, 추천 A·B·C·E → 0.75)을 평균하며, 파트 오분류는 0점입니다. 분류 라벨(일치/담당자 변경)은 위의 엄격한 기준 그대로입니다.
- 파트 오분류 사례(최근 12건)로 프롬프트 개선안을 만들고, **파트 세부담당자 변경 제안**은 AI가 추천한 세부업무 담당자 대신 다른 사람이 3건 이상 처리했고 현재 담당자의 처리 건수보다 많을 때 제안합니다. 둘 다 확인 후 적용 버튼으로만 반영됩니다.
- 프롬프트 버전별 정확도(개선안 번호와 '적용 중' 표시, 정확도가 높은 개선안을 바로 적용)로 적용 전후를 비교합니다. 같은 파일로 과거 사례 검색 자료도 교체합니다.
- Claude 토큰 사용량과 일자별 비용(공식 단가 기준 추정, 단가를 모르는 모델은 미산정으로 표시)을 함께 보여 줍니다.
- 이 도구가 자동 추천한 기록이 있는 티켓만 비교할 수 있습니다.

## 설치와 실행

Ubuntu 등 Linux와 Python 3.11 이상이 필요합니다. 아래 명령은 이 README가 있는 폴더에서 실행합니다.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock.txt
cp .env.example .env
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8080 --workers 1
```

브라우저에서 `http://127.0.0.1:8080`으로 접속해 **Zendesk 계정으로 로그인**합니다(OAuth, 상담원·관리자만).

- 웹 로그인과 접수 계정은 별개입니다. 상담원·관리자 여러 명이 동시에 웹에 로그인할 수 있고(세션은 `web_sessions.json`에 해시로만 저장), 로그아웃하면 그 브라우저만 끝납니다.
- 접수 계정은 서버에 한 명입니다. 접수 계정이 없을 때 처음 로그인한 사람이 맡고, 이후에는 설정의 '내 계정을 접수 계정으로 지정'(다시 Zendesk 로그인)으로 바꿉니다. '자동 접수 멈추기'로 해제하면 다시 지정할 때까지 Zendesk 조회·접수가 멈춥니다. 접수 계정이 아닌 로그인의 Zendesk 토큰은 사용자 확인 직후 폐기합니다.
- 액세스·리프레시 토큰은 `SECRETS_DIR`(기본 `./secrets`)의 `zendesk_login.json`(권한 600)에만 저장하며 Google Sheets·화면으로 보내지 않습니다. 액세스 토큰은 1시간, 리프레시 토큰은 90일이며 만료 5분 전에 자동 갱신합니다. Zendesk가 갱신을 거부하면 접수 계정이 해제됩니다(웹 세션은 유지).
- `ZENDESK_OAUTH_CLIENT_ID`가 비어 있으면 예전처럼 `ADMIN_PASSWORD` 로그인과 `ZENDESK_API_TOKEN`을 씁니다. Zendesk API 토큰은 2027-04-30에 모두 사용 중지되므로 그 전에 OAuth 클라이언트를 등록하세요(`docs/MANUAL.md` 'Zendesk 로그인 설정').
- 다른 PC에서 접속할 때는 HTTPS(`deploy/nginx.conf.example` 참고)와 사내망 접근 제한을 적용하세요. `PUBLIC_URL`이 https이면 세션 쿠키에 Secure가 붙습니다.
- `--workers 1`과 `data/instance.lock`으로 한 서버의 중복 실행을 막습니다. **여러 서버에서 같은 Zendesk·시트로 동시에 실행하면 중복 배정·접수가 발생할 수 있으므로** 한 대에서만 실행하세요.
- 서버를 켜면 저장된 설정이 그대로 적용됩니다. 자동 수집이 켜져 있으면 Zendesk 조회, Claude 호출, Telegram 전송이 바로 재개되고, 실제 접수가 켜져 있으면 Zendesk 변경도 재개됩니다.

## 환경변수

| 변수 | 용도 |
| --- | --- |
| `ZENDESK_OAUTH_CLIENT_ID`, `ZENDESK_OAUTH_CLIENT_SECRET`, `PUBLIC_URL` | Zendesk 로그인(OAuth) 클라이언트와 이 도구의 접속 주소(쉼표로 여러 개). 리디렉션 URL은 각 주소 + `/auth/callback`이며 Zendesk는 `localhost` 외에는 https만 받습니다 |
| `ZENDESK_OAUTH_SCOPE` | 요청 권한. 기본 `read tickets:write`(전체 읽기 + 티켓 쓰기). 티켓 검색은 `tickets:read` 같은 세부 읽기 권한으로는 403이라 전체 읽기가 필요합니다. OAuth 클라이언트 허용 범위에 모두 있어야 합니다 |
| `ADMIN_PASSWORD` | OAuth 설정 전에만 쓰는 웹 관리자 비밀번호 |
| `DATA_DIR` | 실행 기록·배정 이력 디렉터리 |
| `STORE_MODE` | `local` 또는 `sheets` |
| `GOOGLE_SPREADSHEET_ID`, `GOOGLE_APPLICATION_CREDENTIALS` | 설정용 Google 시트 ID와 서비스 계정 JSON 경로 |
| `ZENDESK_SUBDOMAIN` | Zendesk 서브도메인 |
| `ZENDESK_EMAIL`, `ZENDESK_API_TOKEN` | OAuth 설정 전에만 쓰는 API 토큰 계정 (2027-04-30 사용 중지) |
| `SECRETS_DIR` | 접수 계정 토큰·웹 세션 파일 디렉터리 (기본 `./secrets`) |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, `ANTHROPIC_WORKSPACE_ID` | Claude API. 모델은 이미지 입력과 구조화 출력을 지원해야 합니다 (기본 `claude-sonnet-4-6`) |
| `ANTHROPIC_MODEL_TICKET`, `ANTHROPIC_MODEL_IMAGE` | '연결 및 설정 → Claude 모델'에서 고르면 화면 값이 우선합니다(재시작 불필요). 용도별 모델(티켓 분석·가상 테스트 / 배정표 스크린샷·티켓 첨부). 비우면 `ANTHROPIC_MODEL`을 씁니다. `ANTHROPIC_MODEL_SCHEDULE`은 `ANTHROPIC_MODEL_IMAGE`의 예전 이름으로 계속 인식합니다 |
| `ANTHROPIC_EFFORT` (화면에서 고르면 화면 값 우선) | Claude 5.x 모델(`claude-haiku-5-5`, `claude-sonnet-5-5` 등)의 사고량. 기본 `low`. 4.x 모델에는 보내지 않습니다 |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | 알림 봇과 대화방 |
| `ALLOW_LIVE_WRITES` | `true`일 때만 웹의 실제 접수 설정이 동작합니다. 기본 `false` |

첨부 확인(기본 꺼짐, '연결 및 설정 → 자동화'): 켜져 있고 본문 분석 결과가 AI 신뢰도 기준 미만이거나 AI가 검토를 요청한 경우에만, 티켓 댓글의 첨부(본문에 붙여 넣은 이미지 포함) 중 이미지(PNG·JPEG·GIF·WebP)와 PDF를 최대 3개, 파일당 5MB까지 받아 이미지 모델로 다시 분석합니다. 형식은 파일 내용으로 확인하고, 파일 이름은 보내지 않으며, Zendesk 인증정보는 우리 Zendesk 주소에만 보냅니다. 엑셀·한글·워드 등은 제외합니다. 이미지 속 개인정보는 지워지지 않고 전송됩니다. 받은 파일은 저장하지 않으며, 첨부 확인·실패 내용은 추천 근거 맨 앞에 표시됩니다. 첨부 다운로드나 재분석이 실패하면 본문 기준 결과를 유지합니다.

토큰 절감: 티켓 분석에서 시스템 프롬프트와 파트·세부업무 목록은 매번 같으므로 프롬프트 캐시로 보냅니다. 과거 유사 사례 요약은 건당 400자까지만 보냅니다. 프롬프트 버전 이름에 티켓 분석 모델이 붙으므로(`base-0.13-handler@모델`), 모델을 바꾼 뒤 '검토·정확도' 탭에서 버전별 정확도를 비교할 수 있습니다.

실제 키·토큰·서비스 계정 JSON을 저장소, 업데이트 ZIP, 채팅에 올리지 마세요.

## 저장 위치

- **Google Sheets `Settings` 탭**(한 셀의 JSON): 운영 설정, 파트(`parts`: 파트 기본 담당자·Zendesk 선택값 포함), 세부업무 기준(`work_mappings`), PIS 명단(`pis_members`), 날짜별 젠콜(`pis_days`), 개발자 부재(`absences`), Zendesk 필드 매핑(`mapping`), 실제 접수 설정(`live_writes`).
  - 한 셀 50,000자 제한 때문에 14일이 지난 젠콜 일정은 저장할 때 정리되고, 설정이 45,000자를 넘으면 저장을 거부합니다.
  - 개발 담당자 명단은 `Agents`, 날짜 예외는 `Calendar` 탭에 저장됩니다. `Rules`·`Roster`·`Feedback`·`Hospitals` 탭은 0.11부터 쓰지 않습니다(비어 있음).
- 서버를 켜면 즉시 Sheets에서 설정을 읽습니다. 연결하지 못하면 `data/config.json`(마지막으로 Sheets와 맞춘 사본)을 보여 주고 화면에 안내를 띄웁니다. 이 상태에서는 저장과 자동 처리를 하지 않으며, 연결되면 다시 읽습니다.
- **`data/`** (보존·백업 대상, 다른 서버와 나누지 마세요)

| 파일 | 내용 |
| --- | --- |
| `state.json` | 티켓별 처리 상태, Telegram 전송 기록, PIS 배정 이력(`pis`), Zendesk 접수 기록(`writes`). 접수·알림 중복 방지에 사용 |
| `decision_events.json` | 자동 추천 기록. 정확도 비교의 기준 |

## 안전한 적용 순서

1. 자동 수집을 끈 상태에서 **업무·담당자 기준**을 확인합니다. 파트마다 파트 기본 담당자와 세부업무 담당자를 채우고 **기준 저장**을 누릅니다.
2. **운영 달력**에서 젠콜을 등록합니다(스크린샷으로 채우기 또는 드롭다운 선택 후 **젠콜 저장**).
3. **추천 테스트**에서 가상 문의로 요약·세부업무·개발 담당자·자동 PIS·운영팀 담당자 필드 예상값을 확인합니다. Claude 호출 비용이 발생하며, Telegram 전송을 체크하면 `[테스트]` 메시지가 갑니다.
4. 추천 전용 상태로 자동 수집을 켜고 며칠간 결과를 확인합니다. 쌓인 뒤에는 **검토·정확도**에 접수 현황을 올려 비교합니다.
5. **연결 및 설정**에서 필드 매핑과 양식 ID·등록 상태 ID를 입력하고, 선택값을 채운 뒤 **접수 사전 점검**을 통과시킵니다.
6. 답변이 나가지 않는 시험용 Zendesk 계정으로 실제 접수를 먼저 시험합니다. 운영 Zendesk에서 테스트용 변경을 하지 마세요.
7. 운영에 적용할 때 `.env`의 Zendesk 계정과 `ALLOW_LIVE_WRITES=true`를 설정하고 재시작한 뒤, 웹에서 실제 접수를 켭니다. 끌 때는 웹 설정만 꺼도 다음 주기부터 멈춥니다.

알림·Claude 전송 내용은 패턴 기반으로 개인정보를 가리지만 자유 문장의 모든 개인정보를 제거한다고 보장하지 않습니다. 첨부 이미지·영상은 분석하지 않습니다.

## 아직 결정·검증이 필요한 사항

- **파트 기본 담당자**: 비어 있는 파트에서 맞는 세부업무가 없는 문의는 과거 처리자로 추천하고 검토 대상이 됩니다.
- 일부 세부업무는 백업·PIS 담당이 정해지지 않아 비어 있을 수 있습니다.
- **Zendesk 로그인(OAuth)**: 코드는 들어가 있으나 OAuth 클라이언트 등록이 완료되지 않았습니다. 그 전까지는 `ADMIN_PASSWORD` 로그인과 `ZENDESK_API_TOKEN`(2027-04-30 사용 중지)을 씁니다.
- **파트 중복**: `기록`·`약제`·`재활`·`영양`이 별도 파트이면서 엑셀에서는 `진료`의 세부업무로도 있습니다. Zendesk 관련파트 옵션 기준으로 정리가 필요합니다.
- **call 4 (4번째 칸)**: 시트의 '프로비저닝 업무 등' 행에 해당하지만 현재는 티켓 배정 대상입니다. 프로비저닝 전용이면 배정에서 빼야 합니다.
- **젠콜 이력 보존**: 14일이 지난 날짜의 당직표는 설정을 저장할 때 삭제됩니다(과거 당직을 달력에서 볼 수 없음). 변경 전후 설정은 `config_audit.json`에 최근 200건 남습니다.
- **점심 당직 규칙·텔레그램 중복 제거**: 단위 테스트와 가상 티켓으로만 확인했고 실제 운영 티켓으로는 확인하지 못했습니다.
- **명단에 없는 이름**: 기준표에 있으나 담당자 명단에 없는 이름이 있는지 확인하세요.
- **밀린 티켓 묶음 기준 건수**: '한 번의 조회에서 처리할 대기 건수(최대 10)가 기준 이상'을 한 묶음으로 봅니다. 몇 건부터 묶음으로 볼지는 운영에서 정해 설정하세요.
- 최초 감지 이후 사람이 수정한 티켓과 신규가 아닌 티켓은 이미 사람이 다루는 것으로 보고 PIS를 배정하지 않습니다.
- 계정 기본 양식이 자동으로 붙은 신규 티켓은 '양식 미지정'으로 보고 변경합니다.
- `데이터 서비스` 양식 ID, `등록` 사용자 지정 상태 ID, 양식 필수 필드, 선택값은 실제 계정에서 사전 점검으로 확인해야 합니다. 양식의 다른 필수 필드는 자동으로 채우지 않습니다.
- 정확도 비교는 업로드한 자료의 관련파트·담당자 기록이 정확하다는 전제입니다. 자료가 잘못된 티켓은 '제외'하세요.
- 실제 스크린샷 인식 정확도와 실제 Zendesk 접수는 미검증입니다. 웹 화면은 헤드리스 Chrome 렌더링만 확인했고 사람이 보는 실제 화면 점검은 하지 않았습니다.

이전 버전별 변경 사항은 `UPDATE_*.md`를 참고하세요.
