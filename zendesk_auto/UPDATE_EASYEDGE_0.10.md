# 이지엣지 0.10 — PIS 젠콜 자동 배정, 세부업무 연결, Zendesk 실제 접수(기본 꺼짐)

0.9.3 위에 적용합니다. 자세한 기능과 사용법은 `README.md`와 `docs/MANUAL.md`를 참고하세요.

## 적용 직후 바뀌는 동작 (중요)

- **당일 젠콜이 등록되지 않으면 모든 티켓이 '검토 필요'가 되고 Telegram에 PIS가 표시되지 않습니다.** 업데이트 직후 **운영 달력 · PIS 젠콜** 화면에서 젠콜을 먼저 등록하거나, 등록할 때까지 자동 수집을 꺼 두세요.
- 'PIS 젠콜 배정'·'PIS 배분 미리보기' 탭은 없어졌습니다. 젠콜은 운영 달력에서 날짜마다 드롭다운으로 고르고, 스크린샷은 드롭다운을 채운 뒤 **젠콜 저장**으로 확정합니다. 배정 비중은 PIS 명단에서 사람별로 정합니다.
- 다른 양식이 이미 지정된 신규 티켓은 실제 접수 시 변경하지 않습니다(양식이 비어 있거나 계정 기본 양식인 경우만 변경).
- 세부업무 설정을 저장하면 Claude가 세부업무를 함께 판단하고, 세부업무를 정하지 못하거나 기준의 개발 담당·백업과 다른 담당자를 추천하면 '검토 필요'가 됩니다. 세부업무 설정이 비어 있으면 기존과 같이 동작합니다.
- 실제 Zendesk 접수는 `.env`의 `ALLOW_LIVE_WRITES=true`와 웹 설정이 모두 켜져야 동작합니다. 기존 `.env`는 `false`이므로 업데이트만으로 Zendesk가 변경되지 않습니다.
- 밀린 티켓 배정 기준은 0으로 시작합니다(항상 비중 순서 배정). 기준을 넣으면 주담당→백업 후 남는 티켓도 비중 순서로 계속 배정합니다.

- 서버를 다시 켜도 설정이 바로 보입니다. 이전에는 Sheets 모드에서 재시작 후 첫 자동 조회(약 1분)까지 화면에 기본값이 보여 설정이 사라진 것처럼 보였습니다. 이제 시작할 때 Sheets를 바로 읽고, 연결되지 않으면 마지막 저장본을 보여 줍니다.

## 설치

실행 중인 프로그램을 종료한 뒤:

```bash
cd ~/zendesk_auto/zendesk_auto
unzip -o EasyEdge_0.10.zip -d .
.venv/bin/python -m pytest -q
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8080 --workers 1
```

새 패키지 설치는 필요 없습니다. `.env`, `data/`, `secrets/`, `.venv`는 ZIP에 포함되지 않으며 변경되지 않습니다. 기존 설정(Google Sheets)과 자동 수집 여부도 그대로 유지되므로, 자동 수집이 켜져 있었다면 재시작 즉시 실제 Zendesk 조회·Claude 호출·Telegram 전송이 재개됩니다. 브라우저에서 Ctrl+F5로 새로고침하세요.

## 검증

- 자동 테스트 78개 통과(외부 서비스는 모의). 0.1 이후 갱신되지 않아 실패하던 `test_core.py` 5개를 현재 엔진 형식에 맞게 수정했습니다.
- 임시 데이터 디렉터리로 서버를 띄워 로그인·상태·화면 파일 응답을 확인하고, 모든 화면 렌더 함수를 가짜 DOM으로 실행해 오류가 없음을 확인했습니다. 실제 브라우저 클릭 테스트는 하지 않았습니다.
- 실제 Claude 이미지 인식, 실제 Zendesk 쓰기, 실제 Google Sheets 저장은 실행하지 않았습니다.
