# 사전심사 화면 추천과 Telegram 형식 업데이트 0.8

## 변경 내용

- Telegram의 `[주담당]`, `[협업]`, `(검토 필요)`, `(담당자 추천)` 등의 역할·상태 문구를 표시하지 않습니다. 병원, 파트·담당자, 요약, 티켓 링크를 표시합니다. 긴급 문의는 기존처럼 `[긴급]`을 표시합니다. 내부 검토 상태와 사유는 웹 접수 현황에 그대로 기록합니다.
- 제목·본문에 `사전심사 화면`, `사전심사 창`, `사전심사 메뉴`가 명시된 경우 원무 1명, 보험 1명을 추천하도록 Claude 지침과 서버 규칙에 반영합니다. 띄어쓰기 차이는 허용합니다. 각 파트에 모델이 여러 명을 반환하면 첫 번째 유효 후보만 사용합니다.
- 특정 파트 추천이 빠진 경우 배정 가능한 후보가 한 명이면 그 후보를 표시합니다. 후보가 없거나 여러 명 중 적합성을 결정할 근거가 없으면 `담당자 미정`으로 표시하고 내부 검토 대상으로 남깁니다. 부재·제외 담당자는 사용하지 않습니다.
- `사전심사`라는 단어만 있고 화면·창·메뉴가 명시되지 않은 경우에는 서버가 이 규칙을 강제하지 않습니다. Claude가 문의 맥락을 분석합니다. 해당 규칙은 현재 코드에 정의되어 있으며 웹에서 파트 구성이나 인원수를 변경하는 기능은 없습니다.
- 다른 화면의 문의는 기존처럼 복수 파트·복수 담당자 추천이 가능합니다. 별도로 구분되는 다른 업무 파트는 보존합니다.

본 버전은 0.7의 Claude 프롬프트, 제외 담당자, Zendesk 조회 오류 수정, 토큰·정확도 탭, 운영 달력과 기존 추천 전용 동작을 포함합니다. 실제 Zendesk 티켓의 담당자·양식·상태 변경이나 공개 답변 등록은 수행하지 않습니다.

## 적용 및 테스트

1. 기존 프로그램을 Ctrl+C로 종료합니다.
2. ZIP을 `~/zendesk_auto/zendesk_auto`에 복사합니다.
3. 아래 명령으로 덮어쓰고 기존 환경에 맞게 실행합니다.

```bash
cd ~/zendesk_auto/zendesk_auto
unzip -o Zendesk_PreReview_Telegram_update_0.8.zip -d .
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8080 --workers 1
```

`.env`, `data/`, `secrets/`, `.venv`와 Google Sheets 자료는 ZIP에 포함되지 않습니다. 기존 프로그램의 자동 수집 설정이 켜져 있으면 재실행 후 운영 시간에 실제 신규 티켓을 읽고 Claude 분석 및 Telegram 전송을 시작할 수 있습니다. 우선 자동 수집을 끄고 환자정보가 없는 문의로 추천 테스트를 권장합니다. 브라우저 Ctrl+F5로 갱신하세요.

테스트 예시: `사전심사 화면에서 입원료 금액이 계산 화면과 다릅니다.` 원무와 보험에 적격한 담당자를 등록하고, Claude 및 Telegram API 연결 후 가상 테스트에서 확인합니다. Claude는 현재 등록된 담당 범위와 유사 사례를 바탕으로 각 파트의 최적 후보를 선택합니다.

기존에 알림을 보낸 티켓은 중복 방지 때문에 재분석해도 자동 재전송되지 않을 수 있습니다. 중복 방지 기록을 임의 삭제하지 마세요. 개인정보 패턴 제거가 모든 개인정보를 탐지한다고 보장할 수 없으므로 환자정보를 가상 테스트에 넣지 마세요.

78개 자동 테스트는 모의 응답 기반으로 수행했습니다. 실제 Zendesk·Claude·Telegram 및 사용자 웹 브라우저에서의 결과는 아직 검증하지 않았습니다.
